# 確定申告ダッシュボード（microCMS テンプレート）

microCMS をデータベースとして使う、**個人事業主向けの確定申告・源泉徴収ダッシュボード**のテンプレートです。

日々の売上・経費・所得控除の記録を、**e-Tax の入力欄にそのまま転記できる形で合計して表示する**ことだけに特化しています。microCMS の管理画面をそのまま入力 UI として使い、フロントは集計・確認に専念する構成です。

> **⚠️ 本システムは複式簿記の帳簿ではありません**
> 記録を確定申告の様式どおりに合計して表示するだけのツールで、法定帳簿として必要な複式簿記（借方・貸方の仕訳）の代わりにはなりません。青色申告特別控除（65万円・55万円）の適用には、別途、正規の簿記による帳簿の作成・保存が必要です。この但し書きは全ページ上部にも表示されます。

## 何ができるか

| 画面 | 内容 |
| --- | --- |
| ダッシュボード（`/`） | KPI 7指標（売上／源泉徴収税額／必要経費／所得控除／所得金額／未突合件数／登録件数）＋ 2グラフ（月別推移・科目別内訳）。支払調書と未突合の売上をアラート表示 |
| 売上・源泉徴収（`/incomes`） | **支払者 × 種目**の年間合計（第二表「所得の内訳」の1行にあたる単位）。決算書2ページ目の**月別売上**も出力。突合状況をバッジ表示。**税率別の消費税額（参考）**と**2割特例・3割特例の概算納付額**も表示 |
| 経費・決算書（`/expenses`） | **勘定科目別**の年間合計を決算書の印字順で表示。`支払総額 × 事業割合` で算出した**必要経費算入額**が転記する数字。**減価償却の対象は経費計から分離**し、区分の設定漏れ・**少額減価償却特例の300万円超過**・**家事按分100%のリスク**を警告。**税率別の消費税額（参考）**も表示 |
| 所得控除（`/deductions`） | **控除種別**ごとの年間合計。第二表の**保険料区分別の内訳**、医療費の**補填額を差し引いた額**、合計をそのまま入力してよいかの**転記バッジ**を表示 |

全ページ共通で**対象年（暦年 1/1〜12/31）**を切り替えられます。確定申告は5年前まで遡って提出できるため、直近5年分を選択できます。

## 集計の考え方

申告書に転記する数字なので、丸め方と集計基準を明示しています。

### 必要経費算入額

```
必要経費算入額 = 支払総額 × (business_ratio ÷ 100)
```

決算書の損益計算書に載せるのは**この値**です。家事按分した差額（家事分）は経費になりません。**1円未満は明細ごとに切り捨て**ています（合算してから丸めると端数がズレるため）。`business_ratio` 未設定の明細は 100%（全額事業用）として扱います。

### 経費区分と減価償却

`asset_type` が **`経費（10万円未満）`（または未設定）の明細だけ**が「経費計」に入ります。それ以外は減価償却の対象として分離し、`/expenses` の「減価償却の対象」セクションに取得価額を表示します。**当年の償却額は計算していません**（決算書3ページ目で算出してください）。

`asset_type` が「経費」のまま 10万円以上になっている明細は、区分の設定漏れとして警告します（[`AssetTypeAlert`](components/Notice/AssetTypeAlert.tsx)）。判定基準は `DEPRECIABLE_THRESHOLD`、区分ごとの取り扱いは `ASSET_TYPE_GUIDE` にあります。

### 集計期間

確定申告の集計単位は**暦年（1/1〜12/31）固定**です。各 API の `date` フィールドで microCMS 側を絞り込むため、KPI・グラフ・明細がすべて同じスライスになります。`date` が未入力のレコードは集計対象に入りません。

### 日付は JST 固定

[`libs/datetime.ts`](libs/datetime.ts) で日本時間に固定しています。Vercel のサーバー TZ は UTC のため、素の `dayjs()` だと年末年始 0:00〜9:00 の記録が前年に集計されてしまいます。

### 源泉徴収税額

`tax_withheld` に入力された値をそのまま合計します。検算はしていません（源泉徴収は原則 10.21%、100万円超部分は 20.42%）。

### 消費税額（参考）

`/incomes`・`/expenses` に「税率別の内訳（消費税・参考）」セクションがあります。`tax_rate`（`10%` / `8%`）で税込金額をグループ化し、

```
消費税額（参考） = 税込金額 × 税率 ÷ (1 + 税率)   ※ 明細ごとに1円未満切り捨てて合算
```

で割り戻した参考値を表示します。**免税事業者のうちは使いません。** 課税事業者になった場合の試算材料であって、実際の消費税申告書の作成・納税額の計算（2割特例・簡易課税・本則課税のいずれか）は別途行ってください。

- 経費側は事業割合を反映した金額（`businessAmountOf`）を対象にします。仕入税額控除の対象は事業で使った分に限られるためです。
- 経費側は減価償却の対象（`asset_type` が「経費」以外）も**含めます**。所得税の必要経費算入は複数年に分けますが、消費税の仕入税額控除は取得した年にまとめて生じるため、この2つは意図的に扱いが異なります。
- `tax_rate` が未選択の明細は「未設定」としてまとめて表示します。「対象外（不課税・非課税）」を選ぶ選択肢が現在無いため、**「まだ入力していない」のか「対象外」なのかを区別できません**。件数が多い場合は入力を見直してください。

### 2割特例・3割特例の概算納付額（参考）

`/incomes` に、インボイス登録に伴う消費税の経過措置による概算納付額を表示します。個人事業者限定（法人は対象外）で、届出不要・確定申告書への付記のみで適用できます。

```
概算納付額 = 「税率別の内訳」の消費税額（参考）の合計 × 20%（2割特例）または 30%（3割特例）
```
（消費税の確定申告書は100円未満切り捨てが原則のため、この概算値も100円未満を切り捨てています）

対象年に応じて自動的に切り替わります（[`constants/index.ts`](constants/index.ts) の `CONSUMPTION_TAX_RELIEF_BY_YEAR`）。

| 制度 | 対象年（個人・暦年課税期間） | 税率 |
| --- | --- | --- |
| 2割特例 | 2023〜2026年分 | 20% |
| 3割特例 | 2027・2028年分 | 30% |

**2026年分が2割特例の適用最終年です。** 令和8年度税制改正で「3割特例」が新設され、個人事業者に限り2027・2028年分の2年間延長されましたが、法人への延長はありません。どちらも「インボイス登録が理由で免税事業者から課税事業者になった」場合などの要件があるため、表示された金額を使う前に必ず要件を確認してください。経費側の「税率別の内訳」（仕入税額控除の試算用）はこの計算では使いません。

### 少額減価償却資産の特例：年間300万円の上限チェック

少額減価償却資産の特例（措法28の2）は年間合計300万円が上限です。`/expenses` で対象額の合計が上限を超えていると警告します（[`findSmallSpecialOverLimit`](libs/analytics.ts)）。どの資産を特例の対象にするかは任意に選べるため、超過分をどれにするかはユーザー側で判断して `asset_type` を見直してください。

### 家事按分100%のリスク検知

`地代家賃` / `水道光熱費` / `通信費`（[`constants/index.ts`](constants/index.ts) の `MIXED_USE_PRONE_CATEGORIES`）は自宅兼事務所の場合に家事按分が必要になりやすい科目です。これらで `business_ratio = 100` かつ `ratio_basis`（按分の根拠）が未記入の明細を、税務調査で問われやすい典型パターンとして `/expenses` に警告表示します。全額事業用の実態がある場合は根拠を記録すれば警告は出ません。

### 入金管理は対象外

`income.paid_date`（入金日）は表示するだけの参考情報で、集計や入金状況の判定には使いません。売上は発生日（`date`）を基準に全額を計上済みとして扱います。入金・未入金の管理、督促、キャッシュフロー管理は本システムの対象外です（あくまで確定申告の転記を効率化するためのツールという位置づけのため）。

## 申告書の様式との対応と、扱わない範囲

本システムは**転記元**であり、申告書のすべての欄を賄うものではありません。どの欄に対応し、どこが対応していないかを明示します。

### 対応している欄

| 様式 | 欄 | 画面 |
| --- | --- | --- |
| 決算書 1ページ目 損益計算書 | 売上（収入）金額 | `/incomes` |
| 決算書 1ページ目 損益計算書 | 経費の各科目（決算書の印字順に整列）／経費計 | `/expenses` |
| 決算書 2ページ目 | 月別売上（収入）金額 | `/incomes` |
| 決算書 3ページ目 | 減価償却の対象になる資産の一覧（**取得価額まで。償却計算は別途**） | `/expenses` |
| 申告書 第二表 | 所得の内訳（所得の種類／種目／支払者の名称・所在地／収入金額／源泉徴収税額） | `/incomes` |
| 申告書 第一表・第二表 | 社会保険料控除／小規模企業共済等掛金控除（**支払額＝控除額**） | `/deductions` |
| 申告書 第二表 | 生命保険料・地震保険料の**区分別の内訳** | `/deductions` |
| 医療費控除の明細書 | 支払った医療費 − 保険金などで補填される金額（**足切り前**） | `/deductions` |
| 申告書 第一表・第二表 | 寄附金控除（**支払額のみ。2,000円の足切り前**） | `/deductions` |
| 消費税申告書（**参考値。課税事業者向け**） | 税率別の税込・消費税額・税抜金額 | `/incomes`・`/expenses` |

### 扱わない欄（画面上にも明示されます）

「画面に出ない＝0円」という誤解が転記漏れの主因になるため、各ページに [`Coverage`](components/Notice/Coverage.tsx) として一覧表示しています。定義は [`constants/index.ts`](constants/index.ts) の `UNCOVERED_ITEMS` です。

- **売上原価**（期首・期末棚卸高、仕入金額） — 棚卸を持たない業態を前提としています
- **減価償却費の計算** — 資産の一覧と取得価額は出しますが、耐用年数・償却方法・当年分の償却額は扱いません
- **地代家賃・利子割引料の内訳**（3ページ目）、**給料賃金・専従者給与の内訳**（2ページ目）
- **貸借対照表**（4ページ目。青色申告特別控除65万円の適用に必須）
- **青色申告特別控除額の計算** — ダッシュボードの「青色申告特別控除前の所得金額」までを表示します
- **各控除額の計算** — 生命保険料・地震保険料の計算式、医療費と寄附金の足切り
- **人的控除**（基礎・配偶者・扶養）、**雑損控除**、寡婦・ひとり親・勤労学生・障害者控除
- **税額控除**（住宅ローン控除・配当控除・外国税額控除など）、**予定納税額**
- **消費税の申告書の作成・納税額の計算**（税率別の内訳は参考表示のみ。2割特例・簡易課税・本則課税いずれの方式でも、実際の計算・申告は別途行ってください）

### 控除は「支払額」であって「控除額」ではない

`/deductions` の各種別には**転記バッジ**を出しています。

- **支払額＝控除額** … 社会保険料控除、小規模企業共済等掛金控除。表示の合計をそのまま入力できます
- **要計算・区分** … 生命保険料、地震保険料、医療費、寄附金。計算式・足切り・区分記入が挟まります

注意文は [`constants/index.ts`](constants/index.ts) の `DEDUCTION_GUIDE` にまとまっています。

## 残っているスキーマ拡張の候補

第二表の転記に必要なフィールドは一通り揃っています。以下は課税事業者になった場合などに必要になるものです。

### `tax_rate` に「対象外（不課税・非課税）」の選択肢を追加

現在の選択肢は `10%` / `8%` の2つだけです。給与・租税公課・保険料など**そもそも消費税がかからない支出**や、海外向けなど**対象外の売上**を明示的に選べないため、未選択（空欄）と区別がつきません。件数が増えてきたら選択肢を追加することを推奨します（コード側は選択肢が増えても `TAX_RATE_DECIMAL` に無い値として「未設定」扱いを継続するため、追加だけで動きます）。

### `expenses` に `is_electronic`（真偽値）

電子帳簿保存法では、メールや Web で受領した請求書は**電子データのまま保存する義務**があります。紙のレシートをスキャンした場合とは要件が違うため、区別できると安全です。

## 設計上のポイント

- **グラフは値をツールチップに閉じ込めない**。各グラフに「数値で見る」テーブルを併設し、色覚多様性・スクリーンリーダー・印刷のいずれでも値が読めるようにしています。配色も色覚シミュレーション上の識別性を検証済みです。
- **状態は色だけで伝えない**。突合状況・入金状況のバッジは必ず文言（`確認済` / `未確認` など）を伴います。
- **データ0件でも壊れない**。空状態の表示とゼロ埋めした月次軸を用意しています。
- **集計は全件取得**。申告用の合計値なのでページングせず、100件ずつ辿って全件を合算します（暴走防止に取得回数の上限あり）。

## 以下拡張開発例

### 支払調書との突合フロー

現状 `is_verified` は microCMS 側での手動チェックです。年明けに届く支払調書の金額を入力して自動照合し、差額があれば警告する、という流れにすると精度が上がります。

### 画面からのデータ入力

microCMS の管理画面を使わず、ダッシュボードから直接「入金済みにする」「突合済みにする」を操作したい、というのは頻出の要望です。microCMS の **Write API** を Server Actions 経由で叩く構成にすると、閲覧専用から「業務が回る画面」に変わります。

### 領収書 OCR / レシート取り込み

スマホで撮った領収書を microCMS にアップロードし、OCR で日付・金額・支払先を下書き登録する。経費入力の手間が最も大きい部分なので効果が出やすいところです。

### 控除額の自動計算

現在は**支払金額の合計**を表示するに留めています。生命保険料・地震保険料・医療費・寄付金は計算式や足切り額を通して控除額が決まるため、各控除の計算式を実装すれば申告書の該当欄へそのまま転記できます。

### 消費税申告への本格対応

現状は `tax_rate` を使った税率別の内訳（参考値）までです。課税事業者になった場合、2割特例・簡易課税・本則課税のどの方式かによって計算方法が変わるため、方式ごとの納税額試算まで広げられます。本則課税なら `expenses.invoice_number` を使った適格請求書の判定（登録番号が無い相手からの仕入は原則、仕入税額控除の対象外）も組み込めます。

### 帳簿の出力

CSV / Excel での仕訳データ出力、e-Tax の CSV 取込形式への変換など。「結局この画面を見ながら手入力する」を減らす方向の拡張です。

### 通知・リマインド

- 入金予定日を過ぎた売上の督促リマインド
- 予定納税・住民税・国民健康保険料の納付期限通知
- 年末の控除証明書の到着チェック

microCMS の Webhook と Vercel Cron を組み合わせると、追加のサーバーなしで実装できます。

### ログイン・権限管理

現状は URL を知っていれば誰でも閲覧できます。**金額情報を扱うため、公開環境では必ず保護してください。** Vercel の Password Protection（最小構成）か、Auth.js による認証の追加が現実的な選択肢です。
